# Twin selection after vertical navigation

PR151 enables vertical panning, but the generic Analysis body exposed a pre-existing geometric assumption: the whole-body centre plane passes in front of some visible calf surfaces. In an exact-source pointer trace at 320px, the front leg hit was 2.3717988 units from the camera and the old centre-plane cutoff was 2.3575783. The click had zero travel, one pointer, correct canvas coordinates and a front-facing visible triangle. It was rejected solely by the fixed plane. The model's body-centre z was 0.0640463 while the visible leg point z was 0.0498369. These are graphic mesh coordinates, not user measurements.

The new profile derives 129 horizontal cross-sections from actual existing triangles once per loaded body. The near-side plane uses the cross-section's midpoint at each hit's height. It still rejects the opposite side; no arbitrary distance tolerance or unconditional acceptance is added. Empty/invalid geometry retains the previous conservative plane fallback. The profile follows later body transforms, does not change geometry, picking IDs, materials, lighting, data or private textures, and does no work each animation frame.

Real-scene acceptance must retain the original six navigation cases and independently target visible triangle interiors in both Body and Muscles, 320/390/1280px, both themes. It sends actual pointer events through the production picker; the read-only targeting probe exists only in the test Vite transform. Unit tests cover near/far separation, torso-gap protection, four azimuths, indexed/unindexed triangles, parent transforms and unchanged buffers. Synthetic tests and the generic graphic boundary are not physical-device or anatomical validation.
